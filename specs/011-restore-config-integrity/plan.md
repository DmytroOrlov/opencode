# Implementation Plan: Restore Config Integrity

**Branch**: `011-restore-config-integrity` | **Spec**: [spec.md](spec.md) | **Date**: 2026-11-20  
**Status**: Design only; no slice accepted. This plan supersedes the historical FR-005 HOLD. Explicit authorization permits the endpoint-specific error-type evolution. Its verified findings are retained in [research.md](research.md).

## Summary and technical context

Restore atomic global configuration persistence and coherent publication in the existing Effect Config owner; order sparse updates and revisioned fallback intent through the existing admission and recovery owners; expose the two state-specific committed failures only on PATCH where their real boundaries exist through the protocol and generated clients. Runtime: Bun/TypeScript, Effect, JSONC editing, existing filesystem and HTTP API services. Storage: existing global JSONC document; no migration or second durable store. Tests use isolated temporary homes, production services and deterministic barriers. No power-loss durability is promised. Scope excludes new transaction frameworks, broad global error redesign and benchmarks.

**Sources of authority**: this spec; `specs/009-v2-fork-migration/contracts/fallback-config.md`; `specs/010-dual-model-composer-ux/contracts/composer-model-controls.md` and 010 FR-025. 011 intentionally changes the PATCH error contract and pending-retry lookup; 009/010 otherwise remain in force. See [contract](contracts/config-update.md), [state model](data-model.md), and [validation guide](quickstart.md).

## S1 — Atomic configuration commit and publication

**Boundary and handoff.** Core Config owns a typed distinction among precommit failure, committed-unpublished failure and any real committed-published mandatory completion failure, usable directly in core tests. Build a candidate by applying sparse edits to the latest committed document at the protected boundary, validate the entire resulting document, compare for a true no-op, preserve JSONC and unrelated fields, and write a unique temporary file beside the target with preserved mode before atomic rename. Clean precommit artifacts on failure. After rename, never roll back; refresh/invalidate relevant readers before release, or mark the shared protected read path degraded until forward reconciliation. Classify notification and cleanup by actual publication and completion state using the narrow verification in research.md; diagnostic-only optional housekeeping retains success and releases resources. Keep cancellation safe around the commit boundary. Hand off the typed outcome and coherence mechanism to S2 and S3; no HTTP/client change is required for S1 PASS.

**Mapping.** FR-001–004, FR-005 core boundary, FR-010 commit-boundary portion, FR-011–013; Story 1 scenarios 1–6 and core-only 7. S2 owns concurrent ordering in FR-003/004/010; S3 owns wire and clients in FR-005.

**Evidence / V1 preservation.** Extend `packages/core/test/config/config.test.ts` using real temporary JSONC and injected filesystem/publication boundaries. Assert full-document invalidity leaves file, mode and readers intact and valid update succeeds; prove injected temp-write and rename were reached, original bytes/readers survive and no temp remains, then successful retry replaces. Assert comments, format, unrelated properties, mode, omitted/null/legacy fallback, and fresh reader state. Instrument a no-op to prove zero writes, renames and invalidations. Inject real reload, notification and cleanup boundaries after confirmed rename; prove actual state and truthful typed outcome, protected-reader coherence or degradation and reconciliation, diagnostic-only optional housekeeping, and resource release. Test a committed-published mandatory failure only if a real such boundary exists. These are V1 failure-injection guarantees, not counts of tests. Maintain existing assertions.

**Bounded checks.** From repository root: `bun run --cwd packages/core test test/config/config.test.ts`; `bun run --cwd packages/core typecheck`. See quickstart for setup and outcome recording.

**PASS**: all listed core boundary tests and typecheck pass with injection reachability shown and no stale protected reads. **HOLD**: any precommit mutation, leaked temp, false success, postcommit rollback/stale read, or unavailable enforceable publication boundary. S1 does not claim concurrency, HTTP or whole-feature acceptance.

## S2 — Runtime fallback intent, admission and recovery

**Boundary and handoff.** Config reserves update-owner entry order before asynchronous validation; validation may complete independently, and only validated explicit selection/null stages a revision before awaiting exclusive admission. Revision order is based on entry, so late B cannot replace staged C. Retire invalid/cancelled reservations; serialize each sparse commit against latest committed content, using S1's commit/publication boundary. Revision-safe cleanup only removes the current matching intent, exposing latest committed B if C fails, and never erases D. Reuse the shared admission service across graphs; release exactly once and interrupt queued writers, while completing forward after replacement. In `llm.ts`, resolve latest eligible effective intent or committed value after backoff immediately before physical dispatch; snapshot model/variant per attempt. Retain existing compaction, eligibility, attempted-model guards, retry caps and uncertain-tool-effect protections. Hand off these core behaviors to S3; do not require HTTP/client implementation for S2 PASS.

**Mapping.** FR-006–010, FR-003/004 serialized/no-op boundary, FR-011–013; Story 2 scenarios 1–11. Story 1 publication behavior remains S1; full route integration is S3.

**Evidence / V1 preservation.** Extend `packages/core/test/config/fallback-runtime-intent.test.ts`, `packages/core/test/config/config.test.ts`, `packages/core/test/session-generation-admission.test.ts`, and actual runner coverage in `packages/core/test/session-runner.test.ts` / `session-runner-retry.test.ts` as appropriate. Barriers prove A shared lease, B then C reservation, C validated first and observed before commits; B late cannot overwrite C; B invalid/cancelled releases C; B success/C failure exposes B, C success after B failure persists C, and C cleanup cannot erase D. Show sparse fallback/shell merge and B then C reverting to original A is not a stale no-op. Verify omission, null, invalid selection, restart durability, queued cancellation and cross-graph exactly-once release; assert progress and no partial file. Change fallback during backoff and after intent clears, prove latest committed choice at dispatch; change it after dispatch and prove immutable model/variant attribution. Preserve V1/010 negative assertions for same-model and attempted-model guards, caps, compaction and no replay of uncertain tool effects; demonstrate a valid fallback is actually dispatched. No sleeps as synchronization.

**Bounded checks.** `bun run --cwd packages/core test test/config/config.test.ts test/config/fallback-runtime-intent.test.ts test/session-generation-admission.test.ts test/session-runner.test.ts test/session-runner-retry.test.ts`; `bun run --cwd packages/core typecheck`.

**PASS**: S1 prerequisite is present, all listed ordering, cancellation and safety assertions and checks pass. **HOLD**: reservation starvation/leak, stale revision/commit, retargeted dispatched attempt, or unsafe tool replay. HTTP and generated-client assertions are intentionally deferred to S3.

## S3 — HTTP error contract and production integration

**Boundary and handoff.** Map S1 typed outcomes in `packages/server/src/handlers/config.ts` to a PATCH-specific declared 500 in `packages/protocol/src/groups/config.ts`, retaining `_tag: "UnknownError"`, `message`, optional `ref`, and literal codes `CONFIG_COMMITTED_BUT_UNPUBLISHED` and `CONFIG_COMMITTED_WITH_POSTPUBLICATION_FAILURE` for their respective actual states. The latter is exercised only if a real mandatory postpublication failure boundary exists. Generic and precommit failures carry neither code; the schema must decode ordinary generic 500 bodies. Generate Promise/Effect clients with existing tooling, document actual error types, preserve 204 including diagnostic-only optional housekeeping, and preserve affected caller compensation and truthful reconciliation. No global error redesign.

**Mapping.** FR-005, FR-011–014, Story 1 scenario 7 and complete Stories 1–2 integration; S1 owns atomicity and S2 ordering/attempt safety. 009 generated-client and 010 compensation/FR-025 contracts remain applicable except the authorized changes.

**Evidence / V1 preservation.** Extend `packages/server/test/config.test.ts`, `packages/server/test/defect-response.test.ts`, `packages/client/test/promise.test.ts`, `packages/client/test/effect.test.ts`, `packages/app/src/session/composer/selection.test.ts` and `packages/app/src/settings/general/controllers.test.ts` or their owning tests. Prove real precommit, unpublished, optional-housekeeping, generic and success boundaries and, if one exists, the mandatory postpublication boundary. Assert actual state and exclusive code, structural decoding through both clients for each applicable identity, ordinary generic 500 and 204, resource release, and caller compensation and settings behavior without false rollback. Record changed types. Include deterministic held-generation → ordered updates → retry dispatch → PATCH/client trace and preserve V1/010 negative assertions.
