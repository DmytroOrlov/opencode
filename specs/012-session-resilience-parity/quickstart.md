# Validation Guide for Session Resilience Parity

Run the commands from the repository root with the checkout's Bun 1.4.4 and workspace dependencies installed. Test inputs are temporary configuration files, controlled providers and fake streams. Record actual commands and exit codes at implementation and review. Use watchdogs to fail stalled tests and barriers to establish ordering.

## S1 — Embedded configuration

Use independently scoped public `OpenCode.create` hosts. Give A and B distinct working locations, in-memory stores and host-local options. Point both at the same writable config directory. Configure model fixtures without a higher-precedence fallback override. Warm `config.get` in both hosts and retain the original file bytes. Use the existing public `sessions.prompt` and experimental session wait APIs for A, and `experimental.config.update` for B.

1. Gate A's actual LLM call and wait for the provider-start barrier. SessionRunCoordinator has already acquired its real shared lease. Start a valid B PATCH. Wait for accepted stage and exclusive enqueue, and assert zero replacement calls, unchanged old bytes and no completed PATCH. Release A and assert one successful replacement, new bytes and matching effective protected reads from both warmed graphs.
2. Use a controlled primary failure and advance through the existing recovery wait while A still holds admission. Hold the fallback attempt at its dispatch gate. Assert A dispatched B's staged model and variant while the original bytes and zero-renames assertion still hold. Allow the generation to settle, then check B's actual commit and both readers. Stage a newer C while both writers wait and prove A sees C, while B's durable replacement still precedes C's. Delay B validation in a sibling trial so a late older validation cannot replace C.
3. Cancel B while queued and before A reaches fallback selection. Await writer cleanup, assert the abandoned intent cannot appear in the request trace, zero B renames and no temp leftovers. Show a subsequent valid PATCH and generation finish. Add sibling disposal trials for B with a queued write and A while holding a live generation; the surviving host must still use its pair. Cover new-host acquisition while a sibling survives and failed acquisition without a leaked reference. Retain wire-level cancellation and forward-commit tests around a parked rename.
4. With independently scoped A and B on the same resource, wait for A’s actual generation lease and B’s real exclusive enqueue. Interrupt A through `A.sessions.interrupt({ sessionID })` while A stays alive. Observe active interruption, terminal settlement and lease release, then exactly one B commit without a stranded queue entry or temp file. Start another generation in the same live A and require it to acquire admission and finish. Keep the separate host-disposal and queued-writer cancellation cases above.
5. Repeat key same-resource assertions using a directory symlink and a normalized spelling, including a new directory with no config file at startup. Where the filesystem supports case aliases, prove an existing alias through directory identity. Acquire separate transparent FSUtil/filesystem wrappers over the same local backing directory and prove they share admission and intent. Build two virtual stores with identical exposed directory paths and inode/device metadata, each with its own token, and prove independent admission and intent. Try a replacement with missing provenance and require failed startup, closed prerequisite resources and no leaked reference. Use the effective FSUtil for identity and the subsequent Config calls in every test. Use a different-directory control where B commits before A finishes and never changes A's attempt selection. Preserve the same-resource host-local event isolation assertion and repeat isolation controls across distinct resources. Exercise inheritance through the SDK instance selector.

```sh
bun run --cwd packages/sdk test test/embedded.test.ts
bun run --cwd packages/server test test/config.test.ts test/defect-response.test.ts
bun run --cwd packages/core test test/effect/app-node-builder.test.ts test/session-generation-admission.test.ts test/config/config.test.ts test/config/fallback-runtime-intent.test.ts test/session-run-coordinator.test.ts
bun run --cwd packages/core typecheck
bun run --cwd packages/server typecheck
bun run --cwd packages/sdk typecheck
```

Run `bun run --cwd packages/util typecheck` for the filesystem provenance changes. Preserve the two wire abort keepers in `packages/server/test/config.test.ts`, named “a real request abort cancels the queued PATCH inside Config's owner and leaves the next writer unblocked” and “a cancellation arriving mid-commit completes publication and cleanup forward instead of truncating”. The decisive evidence is the pre-release byte/rename trace and physical fallback request, independent of the final file or suite count.

## S2 — Runner recovery

1. Use `RequestExecutor.httpFailure` with 401, URL and no retry override, or send a fake 401 through the real executor. Assert Authentication and non-retryable, then assert one primary, one eligible fallback and zero ordinary retry events with the production runner. The fallback succeeds with the actual selected variant and leaves the session's primary intact.
2. Exhaust the ordinary retry budget through its last allowed primary request with fallback explicitly off. Use `subscribeRetries`, `RETRY_GAPS_MAX` and TestClock. At the final primary request gate, stage a distinct eligible fallback and fail the request. Assert exactly the existing budgeted primary count, unchanged retry event count and one successful fallback. Exercise hard timeout exhaustion and the hook's allowed delay/decision behavior, including inability to bypass a hard cap.
3. Freeze provider failure at boundaries with settled local tools, settled hosted results, unknown executing local or hosted effects, a blocked or declined tool, user cancellation and context overflow. Assert the continuation sees the original tool ID and result with exactly one execution. The unsafe cases must dispatch zero fallbacks. Keep the overflow compaction behavior and verify no fallback for an unrecovered overflow.
4. Exercise a separate ordinary-retry case with a retryable failure or in-budget hook approval and an executing local or hosted tool with unknown effects. Require zero unsafe distinct dispatches and zero replays, count actual executions and verify original failure and settlement. Through the real session execution owner, dispatch X, move/reload or hand off Location during the same active turn, and configure X as the candidate. X remains excluded. Admit a new turn and show X is eligible with its actual variant. Preserve tool-continuation evidence.
5. Replace the intent during a protected read or candidate resolution and verify the latest eligible fallback. In a separate compaction trace let provisional B’s summary physically start, accept C while the summary is in flight and let B’s summary finish with its original attribution. Require the subsequent fallback generation and its telemetry to identify C and its variant, with no generation request, attempt credit, generation telemetry or false record for B. Preserve the unchanged-intent compaction assertions. In a second trace, fully prepare B, accept C before provider consumption, and prove B is neither sent nor counted. Check that C is rebuilt with its correct options, history, model and variant. Confirm variant attribution, reject the active model and repeat identities including the previously attempted primary, and preserve terminal behavior on absent, explicit-off or ineligible fallback. An update after dispatch cannot retarget the in-flight attempt. Replay the persisted projection and preserve existing retry scheduling, assistant identity, resume, and telemetry assertions.

```sh
bun run --cwd packages/core test test/session-runner.test.ts test/session-runner-retry.test.ts test/session-native-compaction.test.ts test/session-telemetry.test.ts test/session-execution.test.ts
bun run --cwd packages/core typecheck
```

After S1 and S2 land, rerun the public SDK test with the same-resource case, in addition to each slice's own gates.

## S3 — SSE transport summaries

1. End established SSE executions through natural completion, local read timeout, request abort, downstream return and other transport error. Record exactly one attempt and verify output/error and cleanup independently. Include a protocol-acknowledged completion without byte EOF, an early return without acknowledged completion, and a failure before headers/SSE establishment with zero attempts.
2. Use the Promise bridge with a gated pending pull and explicit `AbortController`. Arrange return and request abort both before classification and assert `abort`. In separate controls prove pure return is `consumer_cancel`, explicit request abort is `abort`, and abort after an already classified return cannot mutate or duplicate it. Test an owning Effect request interruption separately from iterator return. Await cleanup with fixtures that settle pending reads on cancellation.
3. Use the actual Promise-to-Effect adapter in `packages/ai/src/index.ts` on complete, abort and cancel paths. Exercise synchronous throw, asynchronous rejection and indefinitely pending delivery, with one invocation per execution. Assert preserved output and errors, reader cleanup, no waiting adapter fiber or retained response scope, and no unhandled rejection or retry. For protocol completion before EOF, exercise the actual HTTP `TransportExecution.complete` provider and route acknowledgement.
4. Use the calibrated fixture's five qualifying pulls followed by the stalled sixth pull. Assert its selected threshold is distinct from the initial default, compare elapsed time at the timeout, verify the five-sample basis, and observe a new execution at zero samples with its initial deadline. Preserve configured/disabled/fixed read limits, whole-request timeout, opt-in loopback eligibility, the outlier rule and both clamps. Distinguish missing read times from measured zero.

```sh
bun run --cwd packages/ai test test/http-timeout.test.ts test/promise.test.ts test/http-hooks.test.ts test/splash-telemetry.test.ts test/mlx-telemetry.test.ts test/route.test.ts
bun run --cwd packages/ai typecheck
```

Each independent reviewer records the actual exit status of each relevant command, including the full route suite for protocol completion and incomplete-stream regressions. The AI typecheck includes its dedicated type checks for Promise parity. Use the [diagnostic contract](contracts/sse-diagnostics.md) for classification and field expectations.
